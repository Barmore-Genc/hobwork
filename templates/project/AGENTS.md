# Working on this hob

This is a hob, a Hobwork project: handlers (routes, crons, webhooks, triggers) and a dashboard. Change it on a branch; `merge` tests, merges and deploys it.

## Layout

- `hobwork.json`: entry points, `egress` hosts, `csp` sources and settings, with comments allowed. Only what is declared here runs. `@hobwork/sdk/hobwork.schema.json` describes every field.
- Hob icon: set `icon` in hobwork.json (emoji or image path).
- `src/`: handlers. Each default-exports a function typed `Handler` (`RequestHandler` for routes and webhooks) from `@hobwork/sdk`. It gets `ctx`: `request`, `params`, `payload`, `invocation`, `caller`, `fetch`, `log`, `db`, `files`, `secrets`, `ha`, `device(name)`, `devices()`, `people()`, `person(id)`.
- `ui/`, `index.html`: the dashboard (React + Tailwind) at the hob's app origin, also shown in the Hobwork app. Call routes with `api` from `@hobwork/sdk/browser` (`api.get('spools')`, `api.post('spools', body)`), and native features in the Hobwork app with `native` from `@hobwork/sdk/native`. Style with theme utilities (`bg-bg`, `bg-surface`, `border-border`, `text-fg`, `text-muted`, `bg-accent`, `text-accent-fg`, `text-danger`, ...), not fixed colors or `dark:`. `/_hobwork/` is reserved. A hob that needs no UI deletes both; the build then skips it.
- Other hobs' apps cannot send requests to this app, whatever the method. To let one, list its name in `hobwork.json`: `"crossAppRequests": ["other-hob"]`. The app's own UI and the Hobwork UI need no entry.
- The app runs under a strict Content-Security-Policy: scripts only from the app's own origin (no inline `<script>`, no `eval`, no CDN scripts), and connections, images, fonts and styles from its own origin (plus `data:`/`blob:` images and inline styles). Bundle dependencies with Vite instead of loading them from a CDN. If the UI really needs another source, add it in `hobwork.json`, e.g. `"csp": { "connect-src": ["https://api.example.com"], "img-src": ["https://*.tiles.example.com"] }` (directives: `script-src`, `style-src`, `img-src`, `font-src`, `connect-src`, `media-src`, `frame-src`, `worker-src`, `manifest-src`, `form-action`; sources are `https://host`, `wss://host` or `data:`/`blob:`). `'unsafe-inline'` and `'unsafe-eval'` are only accepted in `script-src` and remove the protection against injected scripts, so avoid them.
- `migrations/`: `0001_name.sql`, ..., applied in order on deploy.
- `tests/`: Vitest. Test files share one module cache; mocks, globals and env vars reset after each test.
- `package.json`: extra npm packages only. Platform packages, `@hobwork/sdk` and `@hobwork/theme` come with the VM.
- `python3` (standard library only, no pip) is there for ad-hoc scripts in the workspace. Handlers, tests and the build stay TypeScript.

## Handlers

- Route `"GET /spools/:id"` answers `GET /api/spools/42` on the app origin, with `ctx.params.id`. A returned `Response` is sent as is, other values as JSON, `undefined` as 204. A thrown error answers 500.
- Crons use 5-field syntax in the host's time zone. Add `"timeZone": "Europe/Istanbul"` for another zone, or `"timeZone": "person"` to run once per person at that time in their own zone (`ctx.payload.person`).
- `ctx.caller` is `{ person, device }` for routes called from the UI by a signed-in person (`device` is set in the Hobwork app), and null otherwise. Key per-person data by `person.id`. `localTime(person)` and `fromLocalTime(person, date, time)` from `@hobwork/sdk` convert to and from their local time.
- Webhooks are called at a secret URL on the hob's own app address (`https://<hob>.<apps host>/_hobwork/hooks/<name>/<token>`) from `rotate_webhook_token`, which returns the full URL once.
- Handlers work like AWS Lambda functions: nothing in memory survives between invocations, and there are no servers, timers or background loops. Keep state in `ctx.db`, use a cron for recurring work.
- `ctx.fetch` only reaches hosts in `egress` and the hosts of assigned secrets. `"host:port"` restricts an entry to one port. Private, LAN and tailnet addresses (like `"100.66.127.125:7912"`, plain http works) are reachable only when the person running Hobwork allows them on the host too; the hob page shows blocked ones crossed out. Secrets are only sent over https. Blocked requests get a 403 and an `egress-blocked` log line. In a workspace, changes to `egress` apply from the next `bash` command after you `commit` them, since the workspace VM is set up from the committed `hobwork.json`. Changes to a secret's hosts apply right away.
- Delete the greeting examples once the hob has its own handlers.

## Data

- `ctx.db.query`, `get`, `run` and `batch` (one transaction) take `?` params as an array or `:name` params as an object. Tests use `createTestDb()` and `createTestContext({ ... })` from `@hobwork/sdk/testing`.
- No interactive transactions. For read-then-write, use one statement (`UPDATE ... WHERE`, `ON CONFLICT`, `RETURNING`) or `batch`.
- One statement per call, no schema changes, `PRAGMA` (except introspection), `ATTACH` or `VACUUM`.
- Migrations are forward-only and additive: a new file per change, never edit a merged one, `STRICT` tables, never drop or rename tables or columns. `merge` refuses anything else.
- `hobwork sql "SELECT ..."` in the workspace queries the branch DB (a copy of production with the branch's migrations).

## Files

- `ctx.files` stores files on the host, for what does not fit a DB row, like uploaded photos: `put(path, body)` (string, `Uint8Array`, `ArrayBuffer`, `Blob` or stream, up to 1 GB; replaces), `get(path)` (`{ size, modified, body, bytes(), text() }` or `undefined`), `stat(path)`, `delete(path)`, `list({ prefix, after, limit })` (path order, at most 1000; pass the last path as `after` for the next page). Errors throw `FilesError` with a `code`.
- Paths look like `photos/2026/cat.jpg`: segments of letters, digits, `.`, `_` and `-`, none starting with `.`. A path is a file or a directory, not both. Keep the file's path in the DB next to the row it belongs to, and pick the name (and extension) in the handler, never straight from user input.
- **Branch previews share production's files.** Unlike the DB, there is no copy per branch: a preview that writes or deletes changes the real files. Write test files under a prefix like `preview/` and clean them up, or test with `createTestContext()`, whose `ctx.files` starts empty in memory (`createTestFiles()` on its own).
- Serve a directory without running a handler with `static` in `hobwork.json`: `"static": { "/photos": { "dir": "photos" } }` serves the file `photos/cat.jpg` at `/photos/cat.jpg` on the app origin, to signed-in users like the UI. Add `"public": true` for anyone with the link (no sign-in). Use it for images, audio, video, PDFs and downloads instead of a route that returns the bytes, which starts the VM and is limited to 24 MB. A mount wins over the UI's files and cannot be under `/api`, `/_hobwork` or `/theme`.
- Static files are shown in the browser only as images, audio, video, PDF, fonts, CSV, JSON, Markdown and plain text. Anything else (HTML, JS, CSS) is sent as a download, so they cannot serve pages or scripts. Uploads through a route are limited to 10 MB per request.
- For photos, 3MF files and other large uploads, declare an upload in `hobwork.json` instead of a route: `"uploads": { "inbox": { "prefix": "inbox/", "maxBytes": 209715200, "types": ["image/*", ".3mf"] } }`. The UI stores files straight into `ctx.files` with `files.upload('inbox/benchy.3mf', file, { onProgress })` from `@hobwork/sdk/browser` (in parts, up to 1 GB, retried on dropped connections; returns `{ path, size, modified }`). A trigger `{ "upload": "inbox", "handler": "src/arrived.ts" }` runs once a file is in, with `ctx.payload` an `UploadEvent` (`upload`, `path`, `size`, `modified`, `contentType`) and `ctx.caller` the person who uploaded it. Scripts (like a folder on a Mac) upload with a token from `rotate_upload_token`: `curl -T <file> -H "Authorization: Bearer <token>" <app origin>/_hobwork/files/inbox/<name>`; their `ctx.caller` is null. An upload replaces a file at the same path, so pick unique paths.

## Secrets

The user creates secrets and their hosts in the Hobwork UI. Find one with `list_secrets` and `assign_secret` it under an env name; if none fits, ask the user to create it. If it lacks a host the code calls, use `request_secret_hosts` and show the user the link. `ctx.secrets.NAME` is a placeholder that Hobwork replaces only in the `Authorization` header (`Bearer`, or `Basic` for a password) and in the headers the secret lists (`list_secrets` shows them as `headers`), and only over https to the secret's hosts. It is never filled into a URL, query string or body, so `?api_key=${ctx.secrets.KEY}` sends the placeholder. Send the secret in a header instead. If the API needs a header the secret does not list, ask the user to add it to the secret in Hobwork. A placeholder in any other header, or over http, fails the request with a 403 (`hobwork_secret_not_allowed`).

## Home Assistant

- Find entities, services and device triggers with the `ha_*` tools. `ha_listen` shows a trigger's real payload.
- Read data HA already has from HA instead of copying it into the DB, unless the user asks for a copy.
- Triggers go under `triggers` in HA automation syntax (`{ "homeassistant": { "trigger": "state", "entity_id": "input_button.desk" }, "handler": "src/desk.ts" }`). The payload is `ctx.payload`.
- A handler may call only the HA services on the hob's list, which starts empty. Add a domain (`light`) or service (`light.turn_on`) with `update_ha_services` before the code needs it, and tell the user; `get_hob` shows the list. A refused call throws `HomeAssistantError` with code `not_allowed` and is logged. `hassio.*`, `homeassistant.*`, `shell_command.*` and `recorder.purge*` are never allowed.
- Act with `ctx.ha.callService`, `getState`, `getStates`, `fireEvent`. Errors throw `HomeAssistantError`. A handler may only call services and fire events on the hob's Home Assistant list (an agent adds `light`, `light.turn_on` or `event:my_hob_changed` with `update_ha_services`); anything else fails with code `not_allowed`. Speak with `tts.speak` or `media_player.play_media`. Calls wait 10 seconds for HA; pass `{ timeoutMs }` (up to 60000) for slow ones. `getState` and `getStates` retry timeouts on their own. For a service that only reads, like `recorder.get_statistics`, pass `{ retries: 2 }` to `callService`; never retry a service that changes something.
- The workspace only reads states (`hobwork ha state|states`). Try service calls with `invoke` after `merge`.

## Devices

`list_devices` shows paired devices and their `capabilities`; a call to one a device does not list fails with `unsupported`. Types are in `@hobwork/sdk` (`Device`, `DeviceEvent`).

- `ctx.device(name).notifications.send({ title, body, actions, data })`, or to a person: `ctx.person(id).notifications.send({ ..., devices: 'all' | 'lastActive' })`, which returns `{ id, devices }` with a result per device.
- Notification options: `id` (your own key, e.g. `print-stopped:42`; sending it again replaces it), `interruptionLevel` (`passive`, `active`, `timeSensitive`), `sound: 'none'` (silent), `thread` (grouping), `open` (a path of the UI a tap opens), `deliverAt` (ISO time; Hobwork holds it until then).
- Actions: `{ id, title, route?, body?, method?, open?, foreground?, destructive? }`. With `route` a tap runs that route (POST, JSON `body` or `{ notificationId, action, data }`) without opening the app, with `ctx.caller` set to whoever tapped. Without `route` or `open`, taps run the `notifications`/`action` trigger.
- `ctx.notifications.update(id, { title, body, actions, data, open })` changes it in place without alerting; `ctx.notifications.withdraw(id)` removes it from every device and cancels a pending `deliverAt`. Withdraw when the event is resolved or someone answered it.
- `ctx.person(id).lastActiveDevice()` is the device the person used last, to reach them where they are; `ctx.person(id).devices()` lists theirs, most recently used first.
- `alarms`: `set({ title, at | time, days, subtitle, tint })`, `timer({ title, seconds, subtitle, tint, repeat: { seconds, title } })` (`repeat` is the ringing timer's second button next to Stop, e.g. `{ seconds: 7200, title: '+2 h' }`: a new countdown with the same ID), `reschedule({ id, seconds, repeat, title, subtitle, tint })` (changes a timer in place; `repeat: null` removes the button, e.g. at a time cap), `cancel({ id })`, `list()`. Store the returned `id` to change or cancel it later. Alarms ring in silent mode and Focus.
- `focus.status()`, `nfc.write({ text, alertMessage, successMessage })` (a Hobwork tag) or `nfc.write({ url, text, ... })` (any http/https/mailto/tel/sms link) / `nfc.read({ alertMessage })` (the person taps a notification and holds the phone to a tag; waits up to 2 minutes), `health.query({ type, from, to })`. Writes read the tag back and answer `{ url, tag?, uid, verified }`, where `uid` is the tag's hardware ID; errors include `cancelled`, `not_writable`, `too_small`, `verify_failed`.
- Calls other than `notifications.send` throw `DeviceError` `timeout` after 30 s; the device may still run them within 10 minutes, and the result goes to the logs.
- Triggers: `{ "device": { "capability": "notifications", "event": "action" } }`, `focus`/`changed`, `nfc`/`scanned` (tags this hob wrote; with `"url": "<prefix>"` also other tags whose link starts with it), `health`/`samples`, `alarms`/`fired`, `alarms`/`stopped`, `alarms`/`repeated` (alarms this hob set rang, someone tapped Stop, or the repeat button started a new countdown; `fired` can arrive late, just before `stopped` or `repeated`), optionally with `"device": "<name>"`. The event is `ctx.payload`.
- Live Activities (iPhone and iPad Lock Screen and Dynamic Island) for something running: `ctx.person(id).liveActivities.start({ id: 'dryer', title: 'Dryer · 65 °C', subtitle, swatches: ['#1E5BD7'], endsAt, startedAt, button: { title: '+2 h', route: '/dryer/extend' }, open: '/dry', pastLimit })` reaches the person's devices that allow them (`ctx.device(name).liveActivities` for one device). The countdown and progress bar run on the phone from `endsAt` and `startedAt`, so do not update for time; update on changes: `ctx.liveActivities.update(id, { subtitle, progress, ... })` (null removes a field) and `ctx.liveActivities.end(id, { content, dismissAt: 'now' })` reach every device that shows it, `ctx.person(id).liveActivities.update/end` only theirs. `progress` alone is pushed at most every 2 percent or 5 minutes; iOS limits pushes. The button runs its route (body `{ activityId, data }`) with `ctx.caller` set to whoever tapped. iOS stops an activity after 8 hours: `pastLimit: 'restart'` (default) starts a fresh one before that, `'stillRunning'` switches to "Still running, ends 06:40". A person who swipes it away does not get it again on that device until it ends. Per-person on/off settings for Live Activities are hob data; `DeviceInfo.capabilities` has `liveActivities` when the device allows them.
- Widget: `"widget": { "route": "/widget" }` in `hobwork.json` names a GET route that returns `WidgetContent` (`{ title, subtitle, lines: [{ text, detail, swatches }], swatches, open, refreshAt }`) for the person in `ctx.caller`; people add the hob's widget to their Home Screen or Lock Screen in the app. It refreshes every 30 minutes (or at `refreshAt`); call `ctx.person(id).widgets.reload()` after a change they should see sooner.
- Shortcuts, Siri, the Action Button and Control Center: `"intents": [{ "id": "where-is", "title": "Where is a spool", "route": "/intents/where", "parameters": [{ "id": "spool", "title": "Spool", "type": "number" }] }, { "id": "scan", "title": "Open Scan", "open": "/scan" }]` in `hobwork.json`. The route gets `IntentRequest` (`{ intent, parameters }`, POST unless `method` says otherwise) with `ctx.caller`, and returns `IntentResult` (`{ say, open }`): `say` is what Siri says, so keep it one short sentence. `opensApp: true` opens the app after the route; an intent with only `open` opens that page.
- Share sheet ("Share to Hobwork" on iPhone and iPad): `"share": [{ "id": "queue", "title": "Add to the queue", "accepts": { "urls": true, "text": false, "files": ["model/3mf", ".3mf", "image/*"] }, "upload": "inbox", "route": "/share" }]` in `hobwork.json`. Files go into the upload `upload` names first (any size up to its `maxBytes`); then the POST route gets `ShareRequest` (`{ target, url, text, files: [{ path, name, size, contentType }] }`, read files with `ctx.files.get(path)`) with `ctx.caller`, and returns `ShareResult` (`{ say }`), which the share sheet shows: one short sentence like "Added Headphone stand to the queue". The upload's triggers run as well, so handle a file in the share route or in the trigger, not both.
- Links to the hob's pages (`https://<hob origin>/spool/78` on an NFC tag or QR code) open the Hobwork app when it is installed. `"appLinks": { "include": ["/spool/*"], "exclude": ["/print/*"] }` limits which paths do (default: every page; `/api` and static directories never). When a page of the hob is open, the app hands it the link instead of loading it: `native.links.onOpened(({ path }) => ...)`. Handle old query forms like `/?spool=78` in the UI.
- Only deployed handlers use devices; tests fake them with `createTestContext({ device: () => ({ alarms: { set } }), personNotifications: () => ({ send }), personLiveActivities: () => ({ start }), liveActivities: { update, end }, notifications: { withdraw } })`. Try with `invoke` after `merge`.

## Native features in the UI

In the Hobwork app (iPhone, iPad, Mac) the UI can use native features through `native` from `@hobwork/sdk/native`. In a browser `native.available` is false and every call rejects with `NativeError` code `unavailable`, so check `native.has(...)` and keep a browser fallback (hide the button, use `navigator.clipboard`, `window.print()`).

- Detect: `native.available`, `native.platform` (`ios`, `macos`), `native.has('haptics')`, `native.has('print', 'pickPrinter')`.
- Errors: `NativeError` with `code` `unavailable` (not in the app, not on this platform), `denied` (the person said no), `cancelled` (they closed the dialog or sheet), `failed`. Treat `cancelled` as a normal outcome, not an error message.
- `native.haptics` (iPhone only): `lift()` when a drag starts, `tick()` over a valid target, `success()`, `warning()`, `error()`, `impact(style, intensity)`.
- `native.print.pdf(pdf, { mediaSize: { width: 62, height: 29, unit: 'mm' }, printer, dialog, jobName })` prints a PDF the hob made (bytes, a `Blob`, or a URL on the app origin, such as a route or a `static` file) through the system print dialog at that paper size, and returns `{ printer, paper }`. Store `printer.id` per person (e.g. alignment offsets per printer) and pass it as `printer` to open the dialog with it selected, or with `dialog: false` to print straight to it. `native.print.printers()` lists printers this hob used on this device, `pickPrinter()` (iOS) opens the printer picker.
- `native.share({ file, filename, url, text })` opens the share sheet.
- `native.clipboard.read()` → `{ text, url }` and `writeText(text)`. Reading asks the person once for this hob (and iOS shows "Allow Paste"), so read only when they tap a paste button. `detect()` → `{ url, text }` says whether there is a link or text without reading it or any prompt (show a "Use copied link" row only then); `paste({ title: 'Paste a link', message })` (iPhone and iPad) shows a sheet with the system Paste button and returns `{ text, url }` with no prompt, `cancelled` when closed.
- `native.notifications.schedule({ id, title, body, interruptionLevel, sound, thread, open, deliverAt })` shows a notification on this device from a button tap, without a handler, and `cancel(id)` removes it. No actions: for those, call a route that uses `ctx.person(id).notifications.send`.
- `native.app.info()` → `{ platform, appVersion, hob, branch, device: { name }, person: { id, name } }`. `device.name` is what `ctx.device(name)` takes.
- `native.nfc` (iPhone): `read({ alertMessage })` → `{ records, uid, tag? }`, `write({ url, text, alertMessage, successMessage })` → `{ url, uid, verified }` (writes, then reads the tag back in the same tap; asks the person once for this hob). Failures are `NativeError` with `code` `cancelled` or `failed` and a `reason` (`not_writable`, `too_small`, `verify_failed`, `busy`) to show in plain words with a retry. `session({ alertMessage, keepOpen: true, onTag, onEnd })` keeps the sheet open and calls `onTag({ records, uid, tag? })` per tag (return a string to change the sheet text, e.g. "Bin 4. Now tap the spool."); `stop(message)` ends it, and iOS ends it after 60 seconds with `onEnd({ reason: 'timeout' })`, so offer to start again. `onScanned(fn)` gets tags scanned while the page is open (iPhone background reading of this hob's tags, the Scan NFC Tag action) without leaving the page. On an iPad or Mac, `has('nfc', 'startSession')` is false; pass `device: 'lastActive'` (or a device name) to `write` or `read` to do it on the person's iPhone: it shows a notification there, and the call waits up to two minutes.
- `native.alarms` (iPhone): `timer({ title, subtitle, seconds, tint, repeat })`, `reschedule({ id, ... })`, `set(...)`, `cancel(id)`, `list()` as `ctx.device(name).alarms`, on this device from a button tap, limited to this hob's alarms. It asks the person once for this hob. `alarms.on('fired' | 'stopped' | 'repeated', fn)` while the page is open; handlers get the same through triggers.
- `native.camera` (iPhone and iPad, not Mac; check `has('camera', 'startScan')` and keep a "Type it in" path): `scanCode({ symbologies: ['upca', 'ean13', 'qr'], guidance })` opens a full-screen scanner over the page and resolves with the first code `{ payload, symbology, bounds }`, or null when the person closes it. `scan({ symbologies, multiple, torch, guidance, regionOfInterest, shutter, buttons: [{ id, label }], onCodes, onButton, onPhoto, onTorch, onEnd })` → `{ ended, stop(), capture({ maxDimension, quality }), setTorch(on), setGuidance(text) }` keeps it open: the page cannot draw over the camera, so put its actions in `buttons` (at most 3, e.g. "Read the label with AI" calling `capture()`) and its status in `guidance`. `photo({ maxDimension, quality })` takes one photo with the system camera. Photos are `{ blob, width, height }` JPEGs (longer side 1600 px by default); send them with `files.upload`. It asks the person once for this hob. Errors: `denied`, `cancelled` (photo closed), `unavailable` with `reason` `unsupported` or `restricted`, `failed` with `reason` `busy`.
- `native.liveActivities` (iPhone and iPad): `start(activity)` shows a Live Activity on this device right away from a tap, such as a card for what the person just picked up; `update(id, changes)` and `end(id, options)` reach every device that shows it, and handlers change it with `ctx.liveActivities` like ones they started. `status()` → `{ enabled, frequentPushes }`; `start` rejects with `denied` when Live Activities are off for Hobwork.
- `native.links.onOpened(({ url, path }) => ...)`: a link to this hob opened the app while this page is open (a tag, a QR code); show `path` instead of reloading.
- `native.on('<capability>.<event>', fn)` listens for events the app sends and returns a function that stops listening.
- Test UI code with `createFakeBridge({ 'haptics.success': () => null, 'print.pdf': () => ({ printer: null, paper: null }) })` from `@hobwork/sdk/native`; call `uninstall()` after the test. `bridge.emit('nfc.tag', { session, records, uid })` fakes events (`camera.codes`, `camera.ended` and the other camera events carry `session` too).
- Offline: `localStorage` and IndexedDB on the app origin survive app restarts in the Hobwork app. To open from the last copy when the host cannot be reached, keep the last data there and queue writes, then send the queue when requests work again. Service workers do not run in the app's web view.
- Any UI library can be added (see Workflow). For drag and drop use pointer events (e.g. `@dnd-kit` with its `PointerSensor`): HTML drag and drop does not work with touch in the app.

## LLMs

`openrouter(ctx)` from `@hobwork/sdk` has `check`, `pick`, `decide`, `embed`, `chat` and `json` (with a zod `schema`; use `.nullable()`, not `.optional()`). It needs a secret with host `openrouter.ai` assigned as `OPENROUTER_API_KEY`. Every call takes `{ timeout, signal }` in its options (or `openrouter(ctx, { timeout })` for every call); a timeout throws `OpenRouterError` with code `timeout`.

Hobwork picks the model for every request, so requests do not name one. People choose the models on the hob's AI page, and agents with `set_ai_model`; `get_hob` shows them under `ai.models`. `check`, `pick` and `decide` go to the decision model, `embed` to the embedding model, the rest to the chat model. To read photos or other images, pass `model: 'vision'` to `chat` or `json` (with `image_url` content parts): it picks the hob's vision model. `'vision'` is the only value `model` takes; model IDs are not accepted.

### What AI is for

Use a model as an `if` or a `pick` inside a handler: evaluating a condition, or categorizing, tagging and filtering. Do not use it for agentic workflows, tool loops, chat interfaces or long generated text. Give it a small, closed question and act on the answer in code.

```ts
const ai = openrouter(ctx)
// true or false
const shipped = await ai.check('Is the order in this email on its way?', { input: email.body })
// exactly one of the choices (an array, or an object of choice to description)
const label = await ai.pick('What kind of email is this?', ['bill', 'shipping', 'promo', 'other'] as const, { input: email })
```

`check(prompt, { input?, threshold?, timeout?, signal? })` returns whether the probability of yes is at least `threshold` (default 0.5). `pick(prompt, choices, options)` returns one of at least two `choices`, typed as their union. Put the question in `prompt` and the data to judge in `input` (a string, object or array; other values go in as JSON). The model treats `input` as data, which makes it harder, not impossible, for text in it to change the question. An answer that does not fit throws `OpenRouterError` with code `invalid_output`; the helpers do not retry, so handle the error or let the invocation fail.

`decide({ state, questions })` asks several questions at once through OpenRouter's Decisions API and returns typed answers: `noul` (probability of yes), `choice` (one of the `criteria` keys, with probabilities) and `score` (the expected level of an ordered scale, lowest first). Decision models read questions literally and cannot count, do arithmetic or compare dates: compute those in code and ask about the result. Ask one judgment per question, about a property of the data, and keep `state` to what the question needs.

`embed(input)` takes a string or an array of strings and returns `{ embeddings, model }`, one vector per input. Store `model` with the vectors: people can change the embedding model, and vectors from different models cannot be compared, so re-embed rows whose model differs from the current one before comparing. Store vectors as `BLOB` columns with `vector.encode(numbers)` from `@hobwork/sdk` (`vector.decode` reads them back) and rank rows in SQL with `vec_distance_cosine(a, b)`, `vec_distance_l2(a, b)` or `vec_dot(a, b)`, for example `SELECT id FROM notes WHERE embedding_model = ? ORDER BY vec_distance_cosine(embedding, ?) LIMIT 10`. These work in handler queries and `createTestDb()`, not in migrations, views or triggers.

### Limits

People limit how many requests and dollars a hob may spend; `get_hob` shows the limits and current spend under `ai`. Every OpenRouter request counts, from workspaces and previews too, so tests fake `ctx.fetch` instead of calling OpenRouter. Past a limit, calls throw `OpenRouterError` with code `hobwork_rate_limit` or `hobwork_spend_limit` (`metadata.retry_after_seconds` says when to try again). Handle these instead of retrying in a loop. Only people change the limits, on the hob's AI page in Hobwork.

## Workflow

1. Create a branch. `main` is deployed and cannot be pushed to.
2. Change code, add tests, run `pnpm typecheck`, `pnpm lint`, `pnpm test`.
3. Commit, then `merge`. It checks, builds, squash-merges and deploys, or returns the failing output.
4. Confirm with `invoke`, `list_invocations` and `get_logs`. Debug from logs, do not guess. A deploy that fails completely is reverted (`auto-revert` in the logs).

Over SSH (`ssh <hob>/<branch>@<host>`), use `hobwork status|diff|commit|merge|logs|invocations`. The workspace has no git directory.

Prefer the platform packages (React, Tailwind, Vite, Vitest, TypeScript, oxlint, zod, date-fns). Add others with `pnpm add` only when none of them does the job. Commit `pnpm-lock.yaml` with the change: merging installs from it and fails without it. Versions released in the last 3 days are not installed, and install scripts of dependencies do not run unless the package is set to `true` under `allowBuilds` in `pnpm-workspace.yaml`.
